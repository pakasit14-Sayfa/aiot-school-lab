## ข้อผิดพลาดที่พิสูจน์ได้และควรแก้ก่อน

1. **RPC งานรายห้องทั้งสองตัวเรียกไม่ได้** — `20260908030200` และ `20260908030300`
   อ้าง `l.created_at` แต่ตาราง lessons มี `published_at` และ `updated_at`.
   ทดสอบการเรียกจริงได้ SQLSTATE 42703 แม้ไม่มีงาน/บทเรียน ทำให้ทั้งหน้าห้องเรียนล้ม
   ต้องกำหนดความหมายเวลาของกิจกรรมก่อนเลือกคอลัมน์ทดแทน ไม่สร้างวันเวลาย้อนหลังขึ้นเอง
   สรุป `20260908030200` ยังมี sum(bigint) → numeric และการ join รายการงานกับทุกวิชาในห้อง
   ที่ควรทดสอบชนิดผลลัพธ์/ยอดซ้ำหลังแก้จุดที่ขวางการเรียกแล้ว

2. **RPC คัดกรองนักเรียนเรียกไม่ได้** — `20260908030600` ใช้ student_id
   โดยไม่ระบุตาราง ซึ่งชนกับ output variable ของ PL/pgSQL (42702).
   `DirectorLearningController.load()` จับ exception แล้วล้างข้อมูลทั้งหน้า
   เบราว์เซอร์ยืนยันข้อความ “โหลดข้อมูลไม่สำเร็จ”.

3. **เปิดเคสแล้วอาจแจ้งสำเร็จผิด** — `openCaseFromFlag()` รับเพียง bool
   จาก service และเรียก load() ที่กลืนข้อผิดพลาด ไม่มีการตรวจ case_id จากรายการ canonical.
   เทสต์ที่จำลอง (ก) อ่านกลับไม่มีเคส และ (ข) อ่านกลับล้มเหลว ล้มทั้ง 2 ข้อ:
   เมธอดคืนสำเร็จแทนการปฏิเสธ ทำให้ปุ่มแสดง success SnackBar ได้

4. **กันเคสซ้ำด้วย title ยังไม่พอ** — SQL และ controller เทียบ reason + detail
   แบบข้อความ เมื่อจำนวนงานค้างเปลี่ยนจะไม่ตรงเคสเดิม ผลทดสอบสร้าง case_id ใหม่จริง.
   ต้องกำหนดตัวระบุสัญญาณที่คงที่/สถานะ active และทดสอบการกดพร้อมกันเพิ่มเติม

5. **รายละเอียดงานยังแสดงความหมายผิด** — `director_classrooms_page.dart`:
   - `pending == 0` ถูกแปลว่า “ตรวจแล้ว” แม้เพียงแค่ส่งครบ หรือไม่มีผู้เรียน
   - ตัวหาร/จำนวนไม่ส่งใช้ room.students แทนผู้เรียนของงาน ทำให้ยอดต่างจาก roster ได้
   - ตัวกรอง “ใกล้ครบกำหนด” และ “เลยกำหนด” ไม่ถูกผลิตโดย mapping สถานะ
   - assignedDate เป็นข้อความ “จากข้อมูลจริง”, description เป็นยอดส่ง ไม่ใช่คำสั่งงาน
   - ถ้า RPC roster โยน error จะค้าง modal ที่ปิดด้วยการแตะภายนอกไม่ได้ เพราะไม่มี catch/finally
   ข้อเหล่านี้มาจากการอ่านโค้ด ไม่ได้อ้างว่าทดสอบสำเร็จผ่าน dialog แล้ว

6. **ตารางสอนเสี่ยงปนห้องต่างชั้นอีกครั้ง** — `_schedulesForRoom()` กลับมาเทียบ
   roomNumber เดี่ยวกับสถานที่สอน โดยไม่มี cohort id หรือ grade ใน RPC ตารางสอน.
   ข้อความเก่าใน survey ที่บอกว่าปิดการจับคู่แบบนี้แล้ว ไม่ตรงกับ working tree ปัจจุบัน

7. **UI และขอบเขตยังไม่ครบ** — ห้องที่ไม่มี homeroom assignment ไม่ขึ้นรายการ,
   คะแนนรายวิชายังว่าง, ไม่มี pagination สำหรับผู้เรียน/เคสจำนวนมาก, ตัวเลข badge
   เมนูมือถือบางส่วนยังคงที่, CCTV และบางข้อความเหตุฉุกเฉิน/สิ่งแวดล้อมยังไม่ใช่ข้อเท็จจริงจากระบบ
