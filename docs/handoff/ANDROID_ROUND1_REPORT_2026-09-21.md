## สภาพแวดล้อมที่ใช้ทดสอบ

- Flutter **3.47.4** (ตรงกับ Mac ตามที่ล็อกไว้), Android SDK 36.1.0, JDK 21 (Android Studio bundled)
- Windows 11, RAM 16GB — **สำคัญ: เครื่องนี้ RAM ไม่พอรันหลาย emulator พร้อมกันสบายๆ** เจอ resource
  contention หลายรอบระหว่างทดสอบ (ดู §5 ปัญหาที่เจอเพิ่มจากใบสั่งงาน)
- Emulator ที่สร้าง: `Pixel_4a_Round1`, `Medium_Phone_Round1`, `Pixel_Tablet_Round1` — ทั้งหมด
  **API 34 (Android 14, "UpsideDownCake")**, Google Play image, ตรงตาม §3

## 0. บล็อกก่อนเริ่ม §4 — แก้แล้ว ดูรายละเอียดใน WORK_LOG.md

`flutter build apk --debug` ล้มตั้งแต่ก่อนเริ่ม เจอ 2 ชั้นปัญหาติดกัน ทั้งคู่แก้แล้วก่อนเริ่ม §4:

   `11.0.3` ก่อน (commit `be3a988` ฝั่ง Mac)
2. **Kotlin source ของ `file_picker` ไม่ถูกคอมไพล์เลย** เพราะ `android.builtInKotlin=false` ชน
   กับที่ file_picker 11 คาดหวัง built-in Kotlin — แก้โดย apply Kotlin plugin เฉพาะโมดูลนั้นจาก
   root `build.gradle.kts` (commit `2d1f820`, Android-only ไม่กระทบ iOS/pubspec)

## 4. §4.4 — แอดมินโรงเรียน

**ทำบางส่วน — ผลไม่ชัดเจน เพราะ session ไม่เสถียรระหว่างทดสอบ** (ดู §7)

| ล็อกอินแอดมิน → หน้าหลัก (ภาพรวม 3 นักเรียน, 2 ครู, 5 อุปกรณ์) | ✅ | โหลดสำเร็จตอนแรกเข้า — [ภาพ 15](audit/android/15_admin_home_overview.png) |
| เมนู "จัดตารางเรียน" (รายการที่ตรงกับ §4.4 ต้องการ) — เปิดครั้งแรก | ❌ | ขึ้น error state สุจริต "โหลดตารางเรียนไม่สำเร็จ กรุณาลองใหม่" (ไม่ใช่ค้างเงียบ, มีปุ่มลองใหม่) — [ภาพ 16](audit/android/16_admin_timetable_load_failed_honest_error.png) |
| หลัง force-restart แอปทั้งตัว → เข้า "จัดตารางเรียน" อีกครั้ง | ⚠️ | ค้างสถานะ loading นาน >1 นาที แล้ว **แอป auto-navigate กลับไปหน้าหลักเอง** โดยไม่มีการกดอะไร |
| หน้าหลักหลังถูก auto-navigate กลับมา | ❌ | ตัวหน้าหลักเองก็ขึ้น "โหลดข้อมูลสรุปไม่สำเร็จ" ตามไปด้วย — กด "ลองใหม่" แล้วยังฟ้อง error ซ้ำ — [ภาพ 17](audit/android/17_BUG_admin_session_instability_home_also_fails.png) |

**สรุป**: เดิมตั้งใจจะรายงานว่า "จัดตารางเรียน" เป็นบั๊กเฉพาะหน้า แต่เมื่อพบว่าหน้าหลัก (ซึ่งโหลด
ผ่านได้ปกติมาก่อนหน้านี้ในเซสชันเดียวกัน) ก็เริ่ม fail ตามไปด้วยหลัง auto-navigate — **จึงไม่ควรฟันธง
ว่าเป็นบั๊กของหน้า "จัดตารางเรียน" เอง** แต่น่าจะเป็นอาการของ session/connection ที่เสื่อมสภาพจากการ
ทดสอบต่อเนื่องยาวนานในรอบนี้ (ผ่าน RAM crisis + restart แอปหลายรอบมาก่อน — ดู §7) **ยังไม่ได้ทำ
ส่วนที่เหลือของ §4.4** (ภาพรวม → เปิดห้อง → ปฏิทินสัปดาห์ → ทดสอบปุ่ม back) เพราะเข้าเมนูไม่ได้เลย
ในสภาพ session ตอนนั้น — ต้องทดสอบซ้ำด้วยเซสชันสั้นๆ สดใหม่ในรอบหน้า

## 7. ปัญหาสภาพแวดล้อมที่เจอเพิ่ม (ไม่ใช่บั๊กแอป แต่กระทบการทดสอบ)

- รันหลาย emulator พร้อมกันบนเครื่องนี้ (16GB RAM) ทำให้ RAM เหลือต่ำกว่า 1GB หลายรอบ ส่งผลให้
  Android ฆ่า/trim โปรเซสแอปเงียบๆ (เช่นเคสตารางสอนข้างบน) — **แนะนำให้รอบทดสอบถัดไปเปิดทีละ
  emulator** แทนที่จะเปิดพร้อมกันหลายตัว
- Emulator ใหม่ (Google Play image) มีงาน background install/compile แอป Google (เช่น YouTube
  ผ่าน `dex2oat`) กิน CPU ช่วงแรกหลังบูต ทำให้แอปดูเหมือนค้างชั่วคราว — รอสัก 1–2 นาทีหลังบูตครั้ง
  แรกก่อนเริ่มทดสอบจะช่วยได้
- **เซสชันทดสอบยาว (~2 ชั่วโมง+ ต่อเนื่อง ผ่านการปิด/เปิด emulator หลายตัว + RAM crisis + restart
  แอปหลายรอบ) ทำให้เกิดอาการโหลดข้อมูลไม่สำเร็จ/แอป auto-navigate กลับหน้าก่อนหน้าเองแบบไม่คงที่ ใน
  หลายหน้าของบทบาทแอดมิน** แม้แต่หน้าที่เคยโหลดผ่านมาก่อนในเซสชันเดียวกันก็เริ่ม fail ตามไปด้วย —
  ไม่แน่ใจว่าเป็นที่ device (secure storage/token cache เสีย), เครือข่ายผ่าน emulator NAT, หรือ
  ฝั่ง backend (เช่น connection pool/rate limit จากการ sign-in/sign-out ซ้ำๆ หลายรอบในเวลาสั้น) —
  **แนะนำรอบทดสอบถัดไปให้จำกัดความยาวเซสชันต่อรอบ (ไม่เกิน ~30–45 นาที) แล้วรีสตาร์ท emulator ทั้ง
  ตัวเป็นระยะ แทนที่จะรันต่อเนื่องยาวและ force-restart แค่ตัวแอป**
