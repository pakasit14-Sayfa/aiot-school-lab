# คำถามถึง agy: ทำไม `~/aiot_dev_dashboard` (แอดมินใหญ่) ถึงต่อ backend จริงแค่ ~15%

จากการตรวจสอบวันนี้ (อ่านโค้ดจริง ไม่ใช่แค่เชื่อรายงาน) พบว่าใน 27 หน้าของ
`~/aiot_dev_dashboard` มีแค่ 4 หน้าที่เชื่อมกับ repository/service จริง
(`dev_dashboard_page.dart`, `device_control_page.dart`,
`learning_platform_page.dart`, `schools_page.dart`) ส่วนอีก 23 หน้า
(รวมทั้งหมดใน `lib/pages/school_admin/*`, และ `devices_page.dart`,
`permissions_page.dart`, `alerts_logs_page.dart`, `settings_page.dart` ที่
เป็นไฟล์ใหญ่หลักพันบรรทัด) ไม่มี service/repository เชื่อมเลย — กดบันทึกแล้ว
ข้อมูลหายทันทีที่ปิดหน้า/reload

อยากทราบจาก agy ตรงๆ ก่อนวางแผนต่อ:

1. **หน้าที่ยังไม่ต่อ backend ทั้ง 23 หน้า มีแผนจะต่อไหม และเรียงลำดับ
   ความสำคัญยังไง?** — ถ้ามี roadmap อยู่แล้วอยากรู้ ไม่อยากไปวางแผนทับ
2. **ทำไมถึงสร้าง UI ที่ดูสมบูรณ์ (หลักพันบรรทัด, ดีไซน์ละเอียด) ก่อนต่อ
   backend?** — เป็นการตั้งใจทำ UI/UX ให้เสร็จก่อนทั้งหมดแล้วค่อยไล่ต่อ
   backend ทีหลัง (design-first) หรือเป็นเพราะแต่ละหน้ายังไม่มี RPC/table
   รองรับจริงในฝั่ง Supabase?
3. **`settings_page.dart` เป็นตัวอย่างที่ชัดสุด** — เป็นแค่
   `TextEditingController` ที่มีค่า default ฮาร์ดโค้ด (`'2.2'`, `'35'`,
   `'45'`) ไม่มี state persistence เลย ตรงนี้ตั้งใจไว้ก่อนว่าจะผูกกับ
   RPC ตัวไหน หรือยังไม่ได้ออกแบบ schema ฝั่งนี้เลย?
4. **`school_admin/*` ทั้ง 9-15 ไฟล์ไม่มีไฟล์ไหนต่อ backend เลยสักไฟล์**
   — เป็นเพราะ scope ของ role `school_admin` ในระบบนี้ยังไม่ได้ตัดสินใจ
   เรื่อง data model (เช่น ตาราง/ความสัมพันธ์ระหว่างโรงเรียน-นักเรียน-ครูใน
   มุมของแดชบอร์ดนี้) ใช่ไหม หรือมีเหตุผลอื่น?

ไม่ได้ถามเพื่อตำหนิ แค่อยากเข้าใจสถานะจริงก่อนวางแผนว่าจะช่วยต่อจุดไหนก่อน —
ถ้าตอบกลับมาพร้อม roadmap/priority ที่มีอยู่แล้วจะดีมาก จะได้ไม่ทำงานซ้ำกัน
