# Parent Redesign Prototype

สถานะ: UI/UX prototype เท่านั้น mock data ทั้งหมด ยังไม่ผูก Supabase จริง

เปิดดู:

- `/prototype/parent-binding` — STK-1 flow ผูกบัญชี (เริ่มจากศูนย์)
- `/prototype/parent-home` — เข้าตรงหน้าแรก (สมมติว่าผูกบัญชี+อนุมัติแล้ว) สำหรับสำรวจ STK-2/3/4/5 และ CON

## ที่มา (2026-08-16)

ตรวจสอบวอลต์กลาง (AIoT-School-Lab-Vault) แล้วพบว่าผู้ปกครองมี UC ของตัวเอง 11 ตัว:

- **STK-1** — ผูกบัญชีผู้ปกครองกับนักเรียน (แบบ B ไม่มี self-signup ต้องมี Binding Code/QR จากโรงเรียน)
- **STK-1a** — อนุมัติการผูกบัญชี — Primary Actor เป็น **ครูประจำชั้น/School Admin/งานทะเบียน ไม่ใช่ผู้ปกครอง** จึงไม่ได้สร้างหน้าในโฟลเดอร์นี้ — [เพิ่มแล้ว 2026-08-16] สร้างที่ `teacher_redesign_prototype/teacher_parent_binding_approval_page.dart` แทน (เมนู sidebar "อนุมัติผูกบัญชี") มี flow ตรวจ/อนุมัติ/ปฏิเสธ พร้อมจัดการกรณี CoI (ผู้อนุมัติเป็นผู้ปกครองของเด็กคนนั้นเอง → บล็อกไม่ให้อนุมัติเอง ต้องส่งตรวจสอบซ้ำเท่านั้น ตาม BR2)
- **STK-2** — ดูคะแนน/ผลการเรียนของบุตร (read-only, เห็นเฉพาะที่ครูยืนยันแล้ว)
- **STK-3** — ดูพัฒนาการ/ความก้าวหน้าของบุตร (สรุปเชิงภาพรวม ไม่ใช่คะแนนดิบ)
- **STK-4** — รับแจ้งเตือนเหตุฉุกเฉิน (ต่อจาก EMG-4)
- **STK-5** — รับรายงานสรุปเป็นระยะ (รายสัปดาห์/เดือน)
- **CON-1** — ขอ/บันทึกความยินยอมผู้ปกครอง (granular ตามวัตถุประสงค์)
- **CON-2** — ถอนความยินยอม
- **CON-3** — ดูสถานะ/ประวัติความยินยอม
- **CON-4** — DSAR ขอเข้าถึง/สำเนาข้อมูล
- **CON-5** — DSAR ขอลบ/แก้ไขข้อมูล

## โครงสร้างไฟล์

- `parent_shared_widgets.dart` — ธีม (teal/emerald แยกจากบทบาทอื่น), `ParentChildMock`/`ParentChildSwitcher` (mock บุตร 2 คนเพื่อสาธิตตัวสลับ — Main Flow ของ STK-2/3/4/5 ทุกตัวเริ่มจาก "เลือกบุตร" เหมือนกัน), `ParentMockPageShell`
- `parent_binding_page.dart` — STK-1 เต็ม flow: กรอก Binding Code/สแกน QR (เดโมโค้ด `SCH-AIOT-2026`) → อีเมล+OTP (เดโม `111111`, จับเวลา 10 นาที, จำกัด 5 ครั้งผิด) → ยืนยันข้อมูลบุตรที่ปิดบังบางส่วน → จบที่สถานะ "รออนุมัติ" เท่านั้น (BR5: ก่อนอนุมัติเห็นข้อมูลบุตรไม่ได้ — หน้านี้จึงไม่มีทางกดผ่านไปหน้า home ได้เลย ต้องเข้า `/prototype/parent-home` แยกต่างหากถ้าจะดูหน้าที่เหลือ)
- `parent_home_page.dart` — หน้าแรกหลังอนุมัติแล้ว มีตัวสลับบุตร + การ์ดทางเข้า STK-2/3/4/5 + CON
- `parent_grades_page.dart` (STK-2), `parent_progress_page.dart` (STK-3), `parent_emergency_alerts_page.dart` (STK-4), `parent_reports_page.dart` (STK-5)
- `parent_consent_status_page.dart` — รวม CON-1 ถึง CON-5 ไว้หน้าเดียวโดยตั้งใจ เพราะเป็น flow ต่อเนื่องกันตามธรรมชาติ: CON-1/CON-2 คือ toggle ยินยอมแยกตามวัตถุประสงค์เดียวกัน (เปิด=ให้, ปิด=ถอน) CON-3 คือส่วนแสดงสถานะ+ประวัติของ toggle เดียวกันนั้น ส่วน CON-4/CON-5 แยกเป็นปุ่ม "ยื่นคำขอ" ต่างหากเพราะต้องผ่านการพิจารณาจาก School Admin ไม่ใช่ toggle ที่มีผลทันที

## ของเก่าที่มีอยู่แล้ว (ไม่ได้แตะ)

ก่อนสร้างโฟลเดอร์นี้ เช็คแล้วพบว่ามีของเก่าคนละชุด:

- `lib/pages/dashboard/parent_dashboard.dart` — dashboard เก่า (era เดียวกับ `teacher_dashboard.dart` เดิม) การ์ด "Coming Soon" สำหรับ STK-2/3/4 ทั้งหมด ไม่ได้ทำจริง
- `lib/pages/redeem_binding_code_page.dart` — หน้าผูกบัญชีจริง (production track ไม่ใช่ prototype) ยังไม่ได้เปิดอ่านละเอียดว่า flow ตรงกับ STK-1 ที่ทำในนี้แค่ไหน
- มี `ParentConsentPage` อยู่แล้วที่อ้างถึงใน `parent_dashboard.dart` (ดูเหมือนเป็นของจริง ไม่ใช่ stub) ยังไม่ได้เปิดอ่านละเอียด

โฟลเดอร์นี้เป็นงาน UX/UI exploration แยกต่างหาก ไม่ได้ตั้งใจแทนที่ของเก่าทันที ถ้าจะรวมเข้าระบบจริงต้องเทียบกับของเก่าก่อนว่าจะ merge หรือแทนที่

## กติกาการใช้งานที่พักงาน (เหมือนโฟลเดอร์ prototype อื่นในโปรเจกต์นี้)

- ห้ามเชื่อม backend หรือข้อมูลจริงในรอบ UI นี้
- ธีม/widget แยกจากบทบาทอื่น ไม่ import ข้ามโฟลเดอร์
- ถ้าหน้าใดผ่านแล้ว ให้ใช้เป็น reference แล้วค่อย rewrite เป็นงานจริงในหน้าจริงแยกอีกครั้ง
