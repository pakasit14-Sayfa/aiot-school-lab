# Executive (ผู้บริหารสถานศึกษา / ผอ) Redesign Prototype

สถานะ: PROTOTYPE SANDBOX — mock data ทั้งหมด ยังไม่ผูก Supabase จริง
(บันทึกไว้ 2026-08-15 โดย Claude Code)

## ที่มา — ตรวจสอบวอลต์กลางก่อนเริ่มสร้าง

ต่างจากฝั่งผู้ดูแลอาคาร (`facility_redesign_prototype/`) ที่มี 7 ยูสเคสเฉพาะ
ทาง (STK-6..12) — ตรวจวอลต์กลาง (`AIoT-School-Lab-Vault`) แล้วพบว่า
**ผู้บริหารสถานศึกษา (ผอ) มียูสเคสเฉพาะทางแค่ตัวเดียว**:

- **LA-9** "ดูรายงานภาพรวมของสถานศึกษา" — Goal: เห็นภาพรวมทั้งโรงเรียน
  (การเรียนรู้ พลังงาน สิ่งแวดล้อม ความปลอดภัย การใช้ระบบ) ในหน้าเดียว
  กรองตามช่วงเวลา/ระดับชั้นได้ — **BR1 (สำคัญ): เห็นภาพรวมระดับโรงเรียน
  เท่านั้น ห้ามเห็นข้อมูลรายคนเชิงลึกที่กระทบความเป็นส่วนตัว**

สิทธิ์อื่นที่ ผอ มีเป็นสิทธิ์ที่ยืมมาจากยูสเคสของ role อื่น ไม่ใช่หน้าจอ
เฉพาะของตัวเอง:
- **LA-11** Export PDF/Excel (Primary Actor: ครู/ผู้บริหาร)
- **SEC-7** รายงานความปลอดภัยทั้งโรงเรียน (Primary Actor: ผู้บริหาร/School
  Admin — เป็นต้นทางที่ STK-10 ของผู้ดูแลอาคารเป็นแค่ตัวกรองย่อยระดับอาคาร)
- **EMG-4 (Exception Flow)** — ผอ เป็นผู้รับแจ้งเตือนฉุกเฉินตั้งแต่แรกร่วม
  กับครูประจำพื้นที่ และเป็น**เส้นทางยกระดับ**ถ้าไม่มีใครรับทราบทันเวลา
  (**ไม่ใช่ผู้ยืนยันปิดหลักตาม EMG-3 ซึ่งเป็นหน้าที่ของครูก่อน** — ผอ เป็น
  แค่ทางสำรอง)
- **SEC-5 (Exception Flow)** — ถ้าครูไม่แน่ใจว่า Alert จากกล้อง AI เป็นเหตุ
  จริงหรือ false positive จะถูกส่งต่อให้ School Admin/ผอ ช่วยตัดสินใจ

**ยังไม่ได้ทำ (เก็บไว้เป็นหน้า 2 ถ้าต้องการ)**: หน้า "ศูนย์แจ้งเตือน/เคสที่
ต้องตัดสินใจ" ครอบคลุม 2 จุดข้างบน (EMG-4 escalation + SEC-5 escalation) —
ยังไม่เริ่มสร้าง

## ยังไม่ได้ทำ (รอทำต่อ)

- **Exception Flow ของ LA-9** ("บางด้านยังไม่มีข้อมูล เช่นยังไม่ติดตั้ง
  เซนเซอร์ → แสดงเฉพาะด้านที่มีข้อมูล") — ยังไม่ implement เป็น demo-state
  switcher แบบที่ทำไว้ในฝั่งผู้ดูแลอาคาร
- หน้า 2: ศูนย์แจ้งเตือน/เคสที่ต้องตัดสินใจ (EMG-4 escalation + SEC-5
  escalation) — ยังไม่เริ่มสร้าง
- ยังไม่มี shell/nav — ตอนนี้เข้าได้ทางเดียวผ่าน `/prototype/executive`
  ตรงๆ (ยังไม่มีเมนู/แถบข้างเหมือนฝั่งผู้ดูแลอาคาร) รอดูว่าจะมีหน้าเพิ่ม
  กี่หน้าก่อนตัดสินใจว่าต้องมี shell ไหม
